# 多智能体事件推演工作台（实验性）

事件推演把研究证据图整理成参与方行动、条件情景和后续观察清单，帮助研究者检查遗漏、寻找二阶影响，并持续复核。输出是研究草稿，不是校准概率、股价预测或交易信号。

本次更新延续已合入的首版推演集成，增加独立工作台和长期复核入口。**当前以 Draft 交付 Pronoia 侧代码；完整运行仍依赖独立网关，网关的公开发布地址与兼容版本尚待确定。**

## 使用流程

1. 点击与「研究 / 回测 / Arena / 前瞻」并列的「推演」，进入 `/simulations`。
2. 选择已有案例与证据图，或展开「试用样例」载入一个历史案例。载入样例只写入本地案例与证据图，不调用模型。
3. 选择 7、30、90 或 180 天观察窗口，填写本轮研究重点，预览自动推荐的参与方；也可以限制为最多 4、6、8 或 10 方。
4. 点击开始后，任务在后台继续。可刷新、取消，或在失败后新建版本重新推演；仅仍有有效检查点的任务适合继续原进度。
5. 阅读情景中的行动、触发与失效条件，展开证据来源和模拟中的当前决策，再复制观察清单。
6. 在「观察与长期复核」中保存原始清单，逐条补充证据和使用评价。

页面地址保留案例与推演版本，也支持独立窗口打开。查看旧版本时，后台进度更新不会把页面切到新版本。尚未提交的研究重点与窗口设置不保存，刷新后需要重新填写。

历史样例涵盖比亚迪、顺丰控股、国泰君安、美的集团、歌尔股份和康美药业，均带公开来源及原始截止日期。资料只是节选，不代表完整证据集，也不代表这些公司的当前状态。修改观察窗口不会把历史截止日期改成今天。详细步骤见 [实际用例验收](mirofish-acceptance.md)。

## 长期复核与指标含义

复核清单冻结原始观察条件，后续记录只追加。每条记录包含观察状态、公开证据及发布时间、复核人、是否值得跟踪和复核耗时。导出包含原始清单、完整记录以及第 30／90／180 天的当期视图。

| 指标 | 用途与边界 |
|---|---|
| 已查明条目 / 全部条目 | 记录已出现或已排除的条件；不等于情景准确率 |
| 值得跟踪条目 / 已评价条目 | 使用者的主观价值评价；未评价条目不计入分母 |
| 累计复核用时 | 记录实际人工成本，不据此推断节省时间 |
| 第 30／90／180 天进度 | 只使用当时已经记录的证据；超过原观察窗口显示「超出原窗口，不计入」 |

在证据截止点超过一天后登记的任务属于历史复盘。历史模型可能知道后续发展，截止过滤不能消除模型知识中的事后信息；这类案例不能作为前瞻有效性证明。

目前不自动抓取后续公告，不自动评价情景覆盖率，也不自动更新原情景。需要更长窗口时创建新的推演版本，不延长旧版本的有效期。

## 运行依赖与配置

```text
Pronoia 证据图 → Pronoia 任务 API → 独立推演网关 → MiroFish / OASIS
                      ↑                  ↓
               工作台与产出物 ← 条件情景、过程状态、复核记录
```

本仓库包含界面、API 代理、任务同步、示例资料和回归测试。它不包含网关进程、MiroFish / OASIS 运行时、分词器资源准备或模型用量账本；仅克隆此 PR 无法完成真实推演。

参考网关目前位于开发者的 FEVER-MiroFish 配套工作区，采用无需 Zep 的产品路径。转为 Ready for Review 前，需要维护者确认网关以独立版本还是仓库内可选服务交付，并提供公开可获取的运行包、安装入口及相应许可证说明。MiroFish 上游为 AGPL-3.0，本 PR 没有复制其源码。

已有兼容网关时，在 Pronoia `.env` 中配置：

```dotenv
PRONOIA_SIMULATION_GATEWAY_URL=http://127.0.0.1:5010
PRONOIA_SIMULATION_GATEWAY_TIMEOUT=15
```

网关连接由后端发起。未启动网关时，普通研究仍可使用，推演预览会显示服务不可用。不要将本机地址直接用于另一台服务器或容器；应填写 Pronoia 后端能够访问的网关地址。

Pronoia 模型连接使用 `LLM_API_URL`、`LLM_API_KEY`、`LLM_MODEL`。旧配套工作区在没有有效 `LLM_API_URL` 时仍可使用完整的 `ARK_API_URL`、`ARK_API_KEY`、`ARK_MODEL` 配置，不会借用模拟服务的密钥。旧 `FEVER_*` 环境变量可回退到对应 `PRONOIA_*`，明确设置的新名称优先；旧浏览器偏好和逻辑库也保留读取兼容。

官方 DeepSeek 端点默认关闭思考模式，模型实验室显式启用思考时仍保留该设置，并在工具续轮中传回推理字段。若本机系统代理无法连接官方 `api.deepseek.com`，可设置 `DEEPSEEK_TRANSPORT=direct` 后重启；该设置只作用于官方端点，并保留 TLS 校验。默认 `system` 维持原代理行为。其他供应商端点不受此规则影响。

## 网关兼容契约

网关需提供以下接口，Pronoia 将本地任务 ID 映射到网关任务 ID：

| 接口 | 作用 |
|---|---|
| `POST /v1/simulations/preview` | 无模型调用的参与方、依据与截止日期预览 |
| `POST /v1/simulations` | 创建或复用后台任务；`rerun=true` 为终态任务创建新版本 |
| `GET /v1/simulations/{id}` | 读取状态、进度、错误与最终结果 |
| `POST /v1/simulations/{id}/cancel` | 请求取消 |
| `POST /v1/simulations/{id}/resume` | 从有效检查点继续，拒绝已退出且无法恢复的模拟 |
| `GET /v1/simulations/{id}/followup` | 读取原始清单、复核记录和当期视图 |
| `POST /v1/simulations/{id}/followup` | 幂等保存原始观察清单 |
| `POST /v1/simulations/{id}/followup/entries` | 校验版本后追加复核记录 |

创建与预览请求包含 `case_id`、`source_graph_artifact_id`、`evidence_graph`、`question`、`as_of`、`horizon_days`、`max_actors`、`market` 与 `mode="quick"`。`max_actors=null` 表示自动推荐。界面固定传入稳定编译器 `product_version="v7"`；实验 API 保留 `v12`，不作为默认。

状态响应包含 `job_id`、`status`、`stage`、`progress`（0–1）、`error`、`finished_at` 和 `result`。终态为 `completed`、`partial`、`failed` 或 `cancelled`。Pronoia 只将有结果的 `completed`／`partial` 写为产出物，不将失败伪装为情景。

复核响应结构与 `frontend/src/types.ts` 的 `SimulationFollowup` 对齐：`snapshot`、`journal`、`checkpoints`、可选 `item_reviews`。未登记时 `snapshot=null` 且列表为空。追加请求带 `expected_revision=journal.length`，网关负责校验原清单、证据时间、记录顺序及版本冲突。持久数据由网关保存，需与 Pronoia 数据库一同纳入备份。

## 稳定性与已知限制

- 假设提炼有完成、无新增、失败和超时状态，最多等待 45 秒；失败仍保留研究正文，历史记录不再无限显示「正在提炼」。
- 界面区分模型网络失败、密钥拒绝、模型不存在、限流、预算耗尽、等待超时和进程退出。恢复原任务与新建推演使用不同入口。
- 条件可能包含无依据的期限、不能公开获取的信号、重复参与方或已完成的历史步骤。待核对提示只是审阅线索，没有提示也不代表已经核实。
- 角色数量、行动次数、单次情景频率和内部一致性都不代表现实概率。当前无证据支持稳定改善市场方向预测或交易收益。
- Pronoia 的自动测试使用模拟网关，不会验证外部运行时是否正确实现上述契约。完整部署仍需用实际网关执行验收。

2026-09-19，本次产品改动通过后端 1,042 项测试、前端 15 项检查和生产构建。可在安装依赖后从仓库根目录复现，无需模型密钥：

```bash
PYTHON_DOTENV_DISABLED=1 PYTHONPATH=.:backend python -m pytest backend/tests -q
cd frontend
npm ci
npm run test:simulation
npm run build
```
