# Pronoia 统一回测平台架构

## 1. 产品定位与页面边界

回测中心是统一市场数据之上的实验平台，不再把模型配置、历史记录和数据导入堆叠在同一个页面。当前拆分为五个独立入口：

1. **事件模型**（`/backtest/event`）：创建事件预测实验，配置平台模型、外部事件模型 API 或已有预测结果。
2. **量化模型**（`/backtest/quant`）：创建平台量化规则或外部量化模型实验。
3. **运行记录**（`/backtest/runs`）：集中查看所有 Run 的状态、进度、指标和详情。
4. **Pronoia 多模型评测 / Model Lab**（`/backtest/model-lab`）：在相同数据与题目下比较不同模型 API。
5. **数据管理**（`/backtest/data`）：登记、校验并冻结事件库和交易数据版本，管理问答问题库。

Arena 保持为独立的跨 Run 比较入口。五个回测页面共享数据版本、执行协议和结果契约，但各页面只展示与自身工作流有关的设置。

## 2. 数据基准与当前导入边界

每个数据集由可变的显示记录和不可变版本组成。Run 必须冻结 `dataset_version` 和内容指纹，不能只引用可能变化的文件路径。

市场数据版本至少声明：

- 市场与资产类型；
- 标的池或指数代码；
- 日 K / 1m / 5m / 15m / 30m / 60m；
- 时区和交易日历；
- 前复权、后复权或不复权；
- OHLCV 字段映射；
- 覆盖区间、行数、标的数和质量报告；
- 来源类型、非敏感来源引用和内容指纹。

事件数据版本还应保存事件发生时间和信息真实可得时间，以防未来信息进入模型。

数据管理页目前只开放已经接通后端校验与版本冻结流程的两种本地导入：

- 事件库：后端可读取的 JSONL 文件；
- 交易数据：后端可读取的 OHLCV CSV 文件。

数据源可以先登记为 `pending`，只有文件真实存在、通过校验并生成冻结版本后才是 `available`。未实现的 API 自动采集入口暂不展示；系统也不能用在线行情、其他频率或合成数据静默替代缺失数据。

### 问题库

数据管理增加第三个“问题库”页签（`/backtest/data?tab=questions`），与事件、行情数据分开。
内置题库包括原核心精选 18 题、完整综合 42 题、共同评测 18 题和特色专项 6 题。
核心题是综合题的子集；题号在各自题库内唯一，不跨题库混用。特色题保留原计分说明，
需要与共同题结果分开解读。

`model_lab/question_bank.py` 及同目录 `question_library.json` 是版本化数据资产。
仓储按 `题库 ID:题号` 幂等补齐缺失数据，不覆盖已有问题、自定义题库和历史实验。
原表的题干、场景、角色、能力标签、交付物及评分依据被保留；不在生产启动时读取 Excel。

用户可搜索分类、展开评分信息、选编独立题库、创建自定义问题、导出 JSON。
前端会话草稿仅保存题库与问题 ID，“用于问答评测”带入 Model Lab，不创建任务或调用 API。
未配置首个 API 时保留草稿；正式创建评测仍由用户确认，并按既有机制冻结题目快照。

## 3. 模型与测试工作流

### 事件模型

事件页只有一个内嵌创建器，不再并排保留“单模型弹窗”和“Model Lab 批次创建器”。
从事件输入、模型与接口、可选问答到确认启动使用同一份草稿；量化页复用编辑器外壳但不展示问答。

接口明确区分：

- Pronoia 平台：使用当前默认 API 和平台 Agent；即使没有单独登记模型连接，也可使用服务端已有配置。
- 已登记的 OpenAI-compatible 连接：由所选 API 驱动 Pronoia 生成事件预测，不冒充不经过 Agent 的裸模型预测。
- 自定义 HTTP JSON 决策服务：使用 Event Decision 契约，不把普通聊天 Base URL 当成预测 endpoint。
- 已有预测结果：校验并评测已提供的方向、置信度与依据，不调用预测模型。

问答默认关闭。开启时显式选择题库、问题、回答模型、Raw API / Pronoia 路径、重复次数和评分方式。
自定义决策 HTTP endpoint 不代表具备聊天能力；问答使用独立、支持聊天的候选连接。
创建接口 `POST /api/bt/event-experiments` 负责关联预测 Run 与独立问答批次，支持保存或开始测试。
问答沿用 fevertest 的八维 100 分量表、原始模型与 Pronoia 回答对照、独立大模型裁判或人工复核。

详情通过 `GET /api/model-lab/backtest-runs/{run_id}/results` 读取关联结果，也兼容已有 Model Lab 预测 Run。
预测结束不停止问答状态更新；完整回答、冻结题干、评分依据和人工评分保存在独立的结果面板。
裁判失败但回答成功时保留回答并允许人工补分，不要求重跑预测。

事件输入与分析引擎分离：

- 事件输入：已注册事件集或手工事件；
- 分析引擎：Pronoia 平台模型、外部 HTTP API 或已完成的预测结果；
- 标准输出：事件、资产、方向、置信度、理由，以及可选目标仓位。

事件预测是必选主测试，问答是可选的第二项测试。启用问答后，预测与问答创建为独立任务并行执行、分别更新状态；任一任务完成即可先查看其结果，另一任务失败或未完成不会掩盖已经生成的结果。

问答测试可以选择候选模型 API、Raw API / Pronoia 回答路径、裁判模型，以及自动、人工或混合评分方式。量化模型不参与问答测试。

在只有事件 Oracle/CAR、没有完整逐 Bar 行情时，结果必须标记为 `event_proxy`。接入冻结行情后，事件决策应转换为标准仓位信号并进入组合撮合引擎，此时才可标记为 `portfolio`。

### 量化模型

量化模型接收冻结 OHLCV，输出 `timestamp + target_weight`。平台量化规则和外部量化模型 API 使用相同输出契约，并由统一执行器应用成交时点、手续费、滑点、仓位约束和基准。该页面只评测信号、仓位及投资表现，不创建问答任务。

外部 API 密钥只允许引用服务端 `PRONOIA_MODEL_SECRET_*` 或相应受控环境变量；真实密钥不能写入 Run、数据库公开字段或浏览器存储。

## 4. Pronoia 多模型评测（Model Lab）

Model Lab 用同一事件集与题库比较不同模型 API 下的 Pronoia：

- 模型连接可登记、验证、启用或停用，并可切换 Pronoia 当前默认 API；
- 批次创建时冻结候选模型、数据版本、题库、回答路径和评分方式，后续修改默认 API 不影响历史批次；
- 预测和可选问答分别生成任务并发执行；
- 问答支持选择题目与重复次数，并在启动前显示候选回答、自动裁判及总调用量；
- 结果页提供独立任务进度、模型/API 对比图、回答明细、八维评分表和人工复核；
- 可导出 Markdown 报告、JSON 原始结果和 CSV 问答明细。

编排演练（dry run）只验证流程，必须明确标记为 Demo，不能进入 Arena，也不能作为正式评测结论。

## 5. 执行协议与结果视图

正式组合回测至少冻结：

- 数据版本与输入内容指纹；
- 信号时点与成交时点；
- 初始资金；
- 手续费与滑点；
- 最大仓位、是否允许做空；
- 日期区间、源数据频率、基准与年化口径；
- 未来扩展的停牌、涨跌停、期货换月和保证金规则。

未被当前执行器真正应用的字段必须列为 `recorded_not_applied`，不能只保存参数却在结果页声称已经生效。

事件与量化共用：总收益、年化收益、基准收益、超额收益、最大回撤、Sharpe、胜率、交易数、成本、资金曲线、回撤曲线、K 线和交易明细。

事件专属：判断正确率、覆盖率、逐事件方向/置信度/理由、Oracle 对照和事件窗口行情。量化专属：规则或版本摘要、信号、仓位、订单、持仓和逐笔成交。

无真实数据时显示 unavailable 和原因，不生成演示曲线。

## 6. Arena 双赛道与时间对齐

Arena 只接收已完成且可复现的正式 Run，并分为两个赛道：

- **事件预测能力**：比较同口径事件 Run 的正确率、覆盖率及逐事件结果；
- **投资表现**：比较可计算真实资金曲线的事件、量化和外部模型 Run。

投资表现赛道支持三种时间对齐：

- **共同区间（intersection）**：只计算所有策略均有真实观察值的重叠时间；
- **完整并集（union）**：展示所有真实历史，某策略没有数据的区间保留空白；
- **手动区间（manual）**：由用户指定起止日期，超出单个策略覆盖的部分明确标记。

对齐只裁剪真实观察值；不插值、不前向填充，也不把短历史策略拉伸成更长历史。日/周/月频率仅用于取真实周期末观察值进行显示降采样，不参与原生或对齐指标的计算。页面同时保留原生指标和对齐区间指标，并显示覆盖率、样本偏短及指数/ETF 存续期等警告。

显式开启时间对齐后，比较协议只把原始日期窗口和源频率外置为对齐条件；正式排名仍严格锁定同一数据内容快照、标的与复权/日历语义、`engine_mode`、benchmark、成交语义、成本、仓位约束和评估器版本。`event_proxy` 不能与逐 Bar `portfolio` Run 在投资表现赛道混排。

Arena 不重新执行策略；它使用 Run 创建时冻结且通过内容指纹校验的预测或组合结果。如果冻结输出缺失或被修改，应拒绝重新计算，而不是用当前状态覆盖历史结论。
